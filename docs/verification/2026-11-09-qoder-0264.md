# Qoder 0.2.64 升级验收

本次将 Qoder 从 `0.2.63` 升级到 `0.2.64`，固定社区插件提交 `e2d15ba653c6c575d2208dd5817ca439bda4b4d4`。Magpie 宿主继续固定 `2c31815c591c73d426c5e9da7f07a9929bce756d`，Bun 为 `1.4.2`。来源与有效文件校验由 `runtime/upstream.lock.json` 维护。上游修复见 [固定提交](https://github.com/magpie-community/plugins/commit/e2d15ba653c6c575d2208dd5817ca439bda4b4d4)。

## 影响与补丁

- 已知模型被官方列表禁用时，插件核对原生额度响应。确认账号额度耗尽后返回 `429 usage limit reached`，沿用 Magpie 原生故障分类与账号选路。当前固定 Magpie 的 `internal/gateway/routing.go` 可将该响应识别为 `failQuota`。额度可用、读取失败或未知模型仍沿用既有续期和 400 路径。
- Windows CLI 缓存同时识别旧目录 `umid-win32-<arch>-<hash>/runtime-info.exe` 与新文件 `runtime-info-win32-<arch>-<hash>.exe`，按架构与文件修改时间选择，排除临时文件。
- 六个完整插件包中只有 Qoder 的入口、README 和 package.json 发生上游内容变化。原有十份补丁全部保留并按原顺序重放，迁移、Markdown 工具解析、精确额度、到期和签到契约保持覆盖。
- 复核发现上游会跳过缺少总额的附加额度池，可能把仍有 60 credits 或内容未知的池误判成耗尽。本次在现有 `qoder.patch` 中补充保守判定，已存在但无法核实的池阻止耗尽结论。可选池缺省或为 null 的语义保留，移除条件同步记录于 `runtime/README.md`。

## 合成验证

所有厂商响应与凭据均为隔离合成数据。旧版运行新回归得到 1 通过、7 失败，复现耗尽时的 400 和新版 Windows 缓存识别问题。未补保护的 0.2.64 在部分额度池回归失败，补充后全部通过。

- 原始来源对象、有效文件哈希及反向补丁校验通过，覆盖 44 份文件、6 个完整包。同步工具在独立临时目录运行，避开当前 linked submodule 的 `core.worktree` 路径解析问题，随后逐字节核对应用内容。
- `python3 tool/check.py` 退出码 0，286 项 Bun 测试、247 项 Flutter 测试、Dart 分析及 Python / Dart / Swift 原生检查通过。
- 新增 9 项回归覆盖耗尽响应、可用/未知额度、未知模型、额度恢复、附加池部分数据和 Windows x64/arm64 新旧缓存选择。原有 Qoder 迁移与工具解析测试继续通过。
- 手工核对绝对值。800 总额减 800 已用等于 0 credits 剩余。300 总额全部已用，加 100 总额且 40 已用的附加池，合计 400 总额、340 已用、60 credits 剩余，仍可用。附加池只返回 60 剩余时保留未知总额，禁止得出账号耗尽结论。

## 验收边界

尚未确认用户账号实际发生过该故障，未用真实耗尽账号执行 Magpie 分组故障切换，也未在安装新版 Qoder CLI 的 Windows 真机运行辅助程序。本次覆盖源码、合成协议和隔离文件系统回归。Windows CI 的应用构建与测试结果另由对应 PR 检查记录，macOS PR 检查覆盖源码行为。真实验收需在自然耗尽的账号上确认官方额度、禁用模型响应与下一账号接续，并在已安装新版 CLI 的 Windows 设备确认辅助程序选择。
