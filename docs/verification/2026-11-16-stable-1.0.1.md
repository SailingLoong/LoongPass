# 1.0.1 release compatibility

The desktop version owner is `pubspec.yaml`: 1.0.1, build 50. The bundled and
independently published Magpie bridge remains 0.2.1, owned by
`runtime/bridge/package.json`; its executable files are unchanged.

## Published artifact and native compatibility

The public npm 0.2.1 tarball was downloaded again. Its SRI matches the reviewed
artifact, and both `index.mjs` and `routing.mjs` match the candidate's bridge:

`sha512-/FDafS557vrjGBukXTajB1v4M3vDi3LtkUygAYSLXnWba3uggufdeUU8SubKQO/1e5PtK+hIy5gIDReJxNvjLQ==`

Installed Magpie 0.1.3346 and official release CLI 0.1.4277 were tested separately
on macOS Apple Silicon with isolated homes and configuration directories. The
new CLI matched both its GitHub asset digest and release SHA256SUMS. Native
processes were denied access to the user's home and account stores.

Each run first installed the public npm package and saved three synthetic local
grants. The actual Dart `MagpieConnection.connect` then selected an equivalent
local path containing `/.`, verified the source and all grants, retired the npm
registration and verified them again. The local source contained the extracted
published package, with bridge implementation bytes matching the application.

The actual Dart routing synchronization and thirteen synthetic gateway requests
covered model discovery, model-applicable expiry priority, same-session reuse,
model isolation, manual model order, streaming, Chat-to-Anthropic tool calls and
401 account failover. Group creation, update, removal and repeated removal of
missing groups completed through native commands.

## Compatibility correction and regression checks

The native installer cleans directory paths, while subsequent `plugin use` and
`plugin options` look up the registered spec. Passing an equivalent `/.` spelling
through unchanged failed against the installed gateway. The existing mock had
accepted that spelling and masked the failure.

Connection and routing now normalize absolute paths with Dart's standard `path`
package before native commands. The already locked path 1.9.1 dependency is
declared directly; its version and bytes did not change. The corrected connection
fixture and routing regression both failed before this production correction
and passed afterward. Both external Magpie versions then passed the native probe.

Windows CI also exposed older list fixtures using root-relative Unix spellings
without a drive. The shared native-list fixture now emits absolute, cleaned
platform paths. Both the ownership check and dependent connection-state test
retain their assertions; no scheduler delay or production verification was weakened.

The full Flutter suite passed 354 tests; 310 native plugin tests passed across
17 files. Dart analysis reported no issues. The distribution smoke test verified
the generated manifest, six-file tarball allowlist and actual extracted imports.

## Acceptance boundary

These checks use synthetic accounts and loopback services. They did not consume
vendor credits, claim rewards, authorize real accounts or certify Windows/Intel
hardware operation. Existing platform-specific real-account records retain their
own scope. Tag CI separately owns both platform builds, native checks, signed
release packages and update-feed publication. Public SOURCE_COMMIT and package
checksums identify the actual published source and bytes.

The npm and desktop versions are independent. Community listing and a future
catalog-reviewed version policy remain upstream decisions; this release does
not claim marketplace inclusion or an enforced catalog version pin.
