# 五平台模型接入与账号池化验证

专项首批为 MiniMax CN、Loomy、WorkBuddy CN、Qoder CN、ZCode BigModel 赠送套餐，
由用户在 2026-11-07 确认，按来源分批交付。本文件逐项记录实际结果。

## Magpie 原生能力探针

使用 `tool/model_pooling_magpie_probe.py`、合成 loopback 上游与独立 XDG 配置。
不读取第三方客户端账号，不调用平台模型，不修改现有 provider 或客户端默认模型。
探针的官方 CLI 候选使用临时本机端口，账号发现关闭；测试结束移除 provider、
终止候选进程并清理临时配置。原先运行的 Magpie 没有被替换或重启。

| 运行程序 | 实际结果 |
| --- | --- |
| 已安装 Magpie 0.1.3101 | `errors=pass` 被 CLI 拒绝：`unknown field errors`；未创建测试来源，不能据此宣称具有安全池化行为 |
| 官方 Magpie CLI 0.1.3244，Apple Silicon | Messages/Chat 文本与 SSE、逐 key 模型目录、双 key 轮换、Chat 工具到 Messages 的转换通过；HTTP 502 与半段 SSE 均只发送一次 |

候选来自官方 release `v0.1.3244` 的 `magpie-cli-darwin-arm64`，
68,202,210 字节；SHA-256 为
`aed558f0849b73e9819ef2e29aae6466d24889ca5eba9721c1754f6b61635b81`，
同时匹配发行资产 digest 与官方 `SHA256SUMS`。

逐账号轮换的六个独立请求，合成账号 A、B 各接收三次；专属模型分别只到达对应账号。
合计 15 个合成调用，实际平台调用为零。这里验证的是 Magpie 原生组合能力，
不是 LoongPass 五平台调用或真实额度验收，也不把工具声明转换当作完整工具执行闭环。

运行时前提是 Magpie 实际支持并启用原生错误透传，不能只凭版本字符串猜测。
本机现有 0.1.3101 不满足该前提；0.1.3244 是本轮经过探针验证的官方候选，
不自动推导其他版本的兼容结果。应用接入与实际客户端验收继续保留这一边界。
