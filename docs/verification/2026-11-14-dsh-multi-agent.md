# 2026-11-14 DSH 多 agent 接入验收

本记录区分连接修复、自动检查、真实模型调用和发布安装。尚未完成的项目不会因为模型目录可见而判为通过。

## 连接修复

本机从桌面启动的 beta 38 原生宿主没有代理环境变量。在本机直连 DNS 失败、系统代理可用时，WorkBuddy 和 MiniMax 的基础请求均超时，Teams 尚未进入子 agent 阶段。

启动器现在按 Magpie 的原生启动约定读取系统手动 HTTP/HTTPS 代理，显式环境变量优先，并保留本机绕过规则。修复后的固定宿主在清除继承代理环境后，通过系统设置访问同一官方上游地址返回 HTTP 200；未使用账号凭据进行此网络探测。

## 自动检查

- 代理新增行为测试先失败，修复后通过；覆盖 macOS、Windows 配置、显式环境优先、IPv6、绕过规则及无效配置。
- 310 项原生运行时测试通过，固定来源及完整插件包校验通过。
- 应用及原生平台回归结果将在本轮完成后补入。

## 真实接入与发布

当前测试使用官方安装版 DeepSeek Harness `0.2.2-rc.2`、Magpie `0.1.3346`；应用候选基于 beta 40 主线，拟交付 beta 41。

Teams 并行子 agent、跨模型工具闭环、会话恢复及安装包验证仍在进行。本记录不表示这些项目已经通过。

Superagent 的独立 profile、默认模型及 Eval / Execution 覆盖模型路径已按官方文档核对；本次不部署 GitHub / 飞书 Sources，不执行外部消息、PR 或常驻恢复验收。该上游是研究原型，版本要求以其当前 manifest 为准。

Windows / Intel 真机多 agent 调用不在本轮已验证范围。系统代理变化需重启应用；PAC 和仅 SOCKS 的自动桥接未实现。
