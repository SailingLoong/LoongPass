# Magpie 连接验收

2026-11-07，在主线桌面样式提交 `46d73f3` 上增加本机模型服务。
测试执行与实际客户端均使用 Claude Code。

## 已实现链路

Claude Code → 本机 Magpie 0.1.3101 → LoongPass 本地 Anthropic Messages 服务
→ MiniMax CN 官方原生接口。Magpie 使用官方 provider 导入机制。

用户明确选择一个来源、账号和官方模型 ID。平台账号模块持有原有账号锁，
负责刷新与身份核验，租约覆盖响应读取。服务仅监听 IPv4 loopback，
校验独立调用密钥，限制请求体大小，并透传 SSE。调用结果未知时返回失败，
保持单次发送。来源扩展通过 `ModelProvider` 契约接入已有账号 owner。

连接启用意图、账号及模型选择和调用密钥由原生私有原子文档保存。
停止时先确认停用意图已保存，再关闭监听。保存失败可重试，写入回执丢失时
读回已提交内容进行核对。模型 ID 编辑草稿保持独立，来源就绪事件保持草稿。

## 实际客户端结果

本轮通过私有测试宿主直接运行生产 `ModelService`、`MiniMaxModelProvider`
和 `MiniMaxAccounts`。宿主从规范账号文件只读取得已保存授权，独立临时存储
连接设置。自动任务由现有应用负责，测试宿主只执行推理。

模型为官方客户端当前配置中的 `MiniMax-M3.1-Flash`。

| 客户端任务 | 实际结果 |
| --- | --- |
| 无工具精确回复 | `LOONGPASS_TEXT_OK`，1 turn，退出码 0 |
| 一次 Bash `printf` 后回复 | 恰好一次成功的 `tool_use` 与匹配的 `tool_result`，最终 `LOONGPASS_TOOL_OK`，2 turns，退出码 0 |
| 流式传输 | 两项任务合计 3 次生产适配器调用，均为 HTTP 200 SSE；客户端完整结束 |
| 重启恢复 | 同端口恢复已保存的启用意图、账号、模型及调用密钥；Magpie 原注册密钥继续通过鉴权 |

规范 MiniMax 国内与国际账号文件前后摘要一致。一次性 Magpie provider 已通过
官方命令移除，私有宿主进程退出、端口关闭，临时连接密钥文件已回收。
账号身份和原始认证材料保留在本机私有验证范围。

此前一轮客户端启动参数将 MCP 配置误作为提示词，该轮精确回复与工具任务
判定无效。更正为独立的 `--mcp-config` 参数及真正空的工具参数后，重新完成
上表全部客户端任务；原始失败记录与更正说明保留于私有证据。
